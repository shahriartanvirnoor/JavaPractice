প্রফেসর জাভা নিয়ে একটা প্রশ্ন ছিলো। java তে আমরা static keyword use করি কেনো? আমি আগে একবার পড়ছিলাম কিন্তু মনে নেই। যে কারণে আমরা variable এর আগে static ব্যবহার করি method আর আগেও কি সে কারণেই static ব্যবহার করি? static আর non-static method এর মধ্যে পার্থক্য কি?

চমৎকার প্রশ্ন! প্রোগ্রামিংয়ের এই কনসেপ্টগুলো মাঝে মাঝে একটু গুলিয়ে যাওয়াটাই স্বাভাবিক। সহজ ভাষায় বলতে গেলে, static মানে হলো এমন কিছু যা কোনো নির্দিষ্ট "Object" বা "Instance"-এর ওপর নির্ভর করে না, বরং সরাসরি Class-এর সাথে যুক্ত।

নিচে আপনার পয়েন্টগুলো ভেঙে বুঝিয়ে বলছি:

১. কেন আমরা static ব্যবহার করি?
সাধারণত, একটি ক্লাসের ভ্যারিয়েবল বা মেথড ব্যবহার করতে হলে আমাদের new কীওয়ার্ড দিয়ে ওই ক্লাসের একটি অবজেক্ট তৈরি করতে হয়। কিন্তু যদি আমরা চাই যে কোনো কিছু অবজেক্ট ছাড়াই সরাসরি ক্লাস থেকে অ্যাক্সেস করা যাবে, তখনই আমরা static ব্যবহার করি।

এর মূল সুবিধা দুটি:

মেমোরি সেভিং: স্ট্যাটিক মেম্বারদের জন্য মেমোরিতে মাত্র একবারই জায়গা বরাদ্দ হয়।

শেয়ারড ডেটা: যখন কোনো তথ্য সব অবজেক্টের জন্য সমান হওয়া প্রয়োজন (যেমন: একটি কোম্পানির নাম বা কলেজের নাম), তখন সেটি স্ট্যাটিক রাখা বুদ্ধিমানের কাজ।

২. Variable বনাম Method: কারণ কি একই?
হ্যাঁ, মূল ধারণাটি একই। আপনি ভ্যারিয়েবলের আগে static কেন ব্যবহার করেন? যাতে সব অবজেক্ট ওই একটি ভ্যারিয়েবলই শেয়ার করতে পারে। মেথডের ক্ষেত্রেও তাই।

Static Variable: এটি ক্লাসের সব অবজেক্টের জন্য একটাই থাকে।

Static Method: এটি ক্লাসের কোনো প্রপার্টি পরিবর্তন বা ব্যবহার করার জন্য অবজেক্ট তৈরির ঝামেলা ছাড়াই কল করা যায়। যেমন: Math.sqrt(16)। এখানে Math ক্লাসের অবজেক্ট তৈরি করতে হয় না, সরাসরি মেথডটি কল করা যায়।

৩. Static বনাম Non-Static Method-এর পার্থক্য
বৈশিষ্ট্য	Static Method	Non-Static (Instance) Method
অ্যাক্সেস করার নিয়ম	ক্লাসের নাম দিয়ে সরাসরি কল করা যায়।	আগে অবজেক্ট তৈরি করতে হয়, তারপর কল করা যায়।
মেমোরি	ক্লাস লোড হওয়ার সময় মেমোরি পায়।	অবজেক্ট তৈরি করার সময় মেমোরি পায়।
অন্য মেম্বারদের ব্যবহার	শুধুমাত্র অন্য static মেম্বারদের সরাসরি ব্যবহার করতে পারে।	static এবং non-static উভয়কেই ব্যবহার করতে পারে।
this কীওয়ার্ড	এখানে this বা super ব্যবহার করা যায় না।	এখানে this ব্যবহার করে বর্তমান অবজেক্টকে নির্দেশ করা যায়।
একটি বাস্তব উদাহরণ (Real-life Analogy)
মনে করুন একটি ক্লাসরুমে অনেকজন ছাত্র (Objects) আছে।

Non-static: প্রত্যেক ছাত্রের নিজের কলম (Variable) বা নিজের লেখার ধরন (Method) আলাদা। এটা তাদের ব্যক্তিগত।

Static: ক্লাসরুমের ব্ল্যাকবোর্ড। এটি সবার জন্য একটাই। কোনো ছাত্র যদি বোর্ডে কিছু লেখে, তবে অন্য সবাই সেটি দেখতে পাবে। বোর্ডটি ব্যবহার করার জন্য কোনো নির্দিষ্ট ছাত্রের অনুমতির প্রয়োজন নেই, এটি ক্লাসরুমের (Class) সম্পদ।

একটি ছোট সতর্কতা:
স্ট্যাটিক মেথড থেকে আপনি সরাসরি কোনো নন-স্ট্যাটিক ভ্যারিয়েবল কল করতে পারবেন না। কারণ স্ট্যাটিক মেথড যখন চলে, তখন সে জানেই না যে কোন অবজেক্টের ভ্যারিয়েবল তাকে ব্যবহার করতে হবে।

আপনার কি কোনো নির্দিষ্ট কোড এক্সাম্পল লাগবে এটা আরও পরিষ্কারভাবে বোঝার জন্য?

তার মানে একটা মেথোডের সব কিছু যেনো একই ক্লাসের অপর মেথোড সরাসরি যেনো ব্যবহার করতে পারে তার জন্যই তো। আমি জানি যে সি তে একটা ফাংশন অপর ফাংশনের ভ্যারিয়াবল কে এক্সেস করতে পারবে না যদি না পয়েন্টর ব্যবহার না করা হয় অথবা গ্লোবাল ভ্যারিয়াবল না করা হয়। জাভা তে কি একই ক্লাসে স্ট্যাটিক গ্লোবাল এর মতো কাজ করে। বিস্তারিত সহজ করে বলো।

আপনি সি (C) প্রোগ্রামিংয়ের সাথে যে তুলনাটি করেছেন, সেটি আপনার বোঝার জন্য দারুণ একটি পয়েন্ট। আপনার ধারণা অনেকটাই সঠিক, তবে জাভার স্ট্রাকচার অনুযায়ী কিছুটা ভিন্নতা আছে। সহজ করে বিস্তারিত নিচে বুঝিয়ে বলছি:

১. স্ট্যাটিক কি গ্লোবালের মতো কাজ করে?
হ্যাঁ, একদম ঠিক ধরেছেন। সি-তে যেমন আমরা ফাংশনের বাইরে Global Variable ডিক্লেয়ার করি যেন সবাই সেটি ব্যবহার করতে পারে, জাভাতে static ভ্যারিয়েবল ঠিক সেই কাজটাই করে।

সি-তে গ্লোবাল ভ্যারিয়েবল পুরো প্রোগ্রামের যেকোনো জায়গা থেকে পাওয়া যায়।

জাভাতে static ভ্যারিয়েবল ওই পুরো ক্লাসের জন্য গ্লোবাল হিসেবে কাজ করে। এমনকি অন্য ক্লাস থেকেও (যদি পাবলিক হয়) একে সরাসরি ব্যবহার করা যায়।

২. মেথড কি একে অপরের সবকিছু ব্যবহার করতে পারে?
এখানে একটি সূক্ষ্ম বিষয় আছে। মেথডের ভেতরকার সব ভ্যারিয়েবল (Local Variables) কিন্তু অন্য মেথড সরাসরি পায় না। কিন্তু আপনি যদি কোনো ভ্যারিয়েবলকে মেথডগুলোর বাইরে এবং ক্লাসের ভেতরে static হিসেবে লিখে রাখেন, তবে ক্লাসের সব মেথড তাকে সরাসরি ব্যবহার করতে পারবে।

৩. একটি মেথড কি অন্য মেথডকে ব্যবহার করতে পারে?
হ্যাঁ, জাভাতে একই ক্লাসের ভেতরে এক মেথড থেকে অন্য মেথডকে কল করা যায়। তবে এখানে static-এর একটি নিয়ম আছে:

Static Method: সে কেবল অন্য Static মেথড বা ভ্যারিয়েবলকে সরাসরি ডাকতে পারে। (কারণ সে জানে এরা সবাই ক্লাসের অংশ)।

Non-Static Method: সে Static এবং Non-static—উভয়কেই সরাসরি ডাকতে পারে।

সি (C) বনাম জাভা (Java): একটি সহজ তুলনা
বৈশিষ্ট্য	সি (C Language)	জাভা (Java Language)
সবার জন্য কমন ডেটা	Global Variable ব্যবহার করা হয়।	Static Variable ব্যবহার করা হয়।
মেমোরি শেয়ারিং	গ্লোবাল ভ্যারিয়েবল সব ফাংশন শেয়ার করে।	স্ট্যাটিক ভ্যারিয়েবল সব অবজেক্ট শেয়ার করে।
অ্যাক্সেস	সরাসরি নাম ধরে ডাকা যায়।	ClassName.variableName দিয়ে ডাকা যায়।
৪. কেন জাভাতে পয়েন্টার লাগে না?
সি-তে এক ফাংশনের ভ্যারিয়েবল অন্য ফাংশনে পরিবর্তন করতে হলে পয়েন্টার লাগত (Call by Reference)। জাভাতে static ব্যবহার করলে পয়েন্টার ছাড়াই সবাই একই ডেটা অ্যাক্সেস এবং পরিবর্তন করতে পারে। কারণ জাভা রানটাইম জানে যে, এই static ডেটাটি মেমোরির একটি নির্দিষ্ট জায়গায় (Method Area) একবারই রাখা হয়েছে।

সংক্ষেপে: আপনি যদি চান কোনো ডেটা বা ফাংশন আপনার ক্লাসের সব মেম্বার শেয়ার করবে এবং সেটি ব্যবহারের জন্য আলাদা কোনো "অবজেক্ট" বা "পয়েন্টার" লাগবে না, তবেই আপনি static ব্যবহার করবেন।
